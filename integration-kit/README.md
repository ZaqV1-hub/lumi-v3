# Lumi Integrações

Este é o projeto de trabalho para desenvolver funcionalidades externas da Lumi de forma independente do núcleo. O código aqui não altera sozinho a versão dos clientes. A equipe revisa o serviço e testa a integração em homologação antes de habilitá-lo. As regras de colaboração estão em `docs/arquitetura-e-colaboracao.md`, e o protocolo em `docs/contrato-de-integracoes.md`. Não há aprovação automática nem conexão de implantação neste projeto.

O pacote inclui os serviços atuais de pesquisa web, consultas/e-commerce Rincão e agenda Estância, além do handover falso e dos adaptadores disponíveis para os sites. O serviço de projetos Brevia ainda depende de modelos internos e não está incluído como serviço independente. O núcleo, seu banco, conversas, modelo de IA, painel e credenciais não foram copiados. As integrações reais precisam de configuração e acessos próprios de homologação; apenas copiar o código não cria esses acessos.

Para começar sem nenhum sistema real, crie um ambiente Python e instale `pip install -r requirements.txt`. Copie `.env.example` para `.env` e configure uma chave de desenvolvimento. Inicie `python -m uvicorn example_service.api:app --host 127.0.0.1 --port 8010`. O exemplo publica uma disponibilidade fictícia, não cria reserva e não envia e-mail ou WhatsApp.

No outro terminal, configure a mesma chave em `SERVICE_SECRET`. Execute `python check_service.py --service http://127.0.0.1:8010` para verificar os contratos. Depois execute `python check_service.py --service http://127.0.0.1:8010 --tool consultar_disponibilidade_demo --input example-request.json`. O simulador faz a chamada HTTP no formato do núcleo, sem usar IA ou gravar na Lumi. Use somente entradas fictícias; um POST a um serviço real pode ter efeitos reais. Esse teste não habilita nada no atendimento.

Para estudar os serviços existentes, os comandos de entrada são `python -m uvicorn services.web_tools.api:app --port 8004`, `services.rincao.api:app --port 8003`, `services.estancia.api:app --port 8006` e `services.handover:app --port 8001`. Eles usam as configurações privadas previstas no código. Não os aponte para banco de produção durante desenvolvimento e não reutilize as portas de uma Lumi já ligada na mesma máquina. O e-commerce Estância também precisa do site de homologação, separado deste serviço de agenda.

Na entrega, informe o que mudou, como executar, quais acessos são necessários, quais testes passaram, limitações e qual versão deve ser revisada. Use um branch ou repositório de trabalho. A equipe revisa a versão, testa em homologação e combina a liberação. Publicar um contrato não autoriza habilitar permissões ou alterar a configuração de um cliente. O arquivo `manifest.json` identifica os arquivos da cópia inicial; mudanças posteriores precisam de uma nova versão identificada.
